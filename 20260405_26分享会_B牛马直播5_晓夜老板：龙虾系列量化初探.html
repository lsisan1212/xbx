龙虾（多智能体）核心定义与基础配置

点击展开詳情

1. 核心定义

龙虾≠OpenCore单一方案，而是以多Agent为核心的协同系统，通过角色分工实现复杂量化任务，核心三要素：Token（模型选择）、内存/硬盘（存储）、CPU算力（运行效率）

2. 模型选择优先级

  • 首选：Cloud（OPS 4.6）＞GPT（5.4）＞千问+MinMax组合
  • 避坑：不推荐本地部署模型（算力要求高）、小众模型（提示词适配成本高）
  • 白嫖方案：公益站API（1万次/个，3-4个够用）、指纹浏览器绕过GPT限制

3. 硬件要求

深度用户需≥4C4G服务器（2C2G不足以支撑回测），建议本地部署龙虾（算力本地+服务器托管，兼顾效率与稳定性）

多Agent角色配置与协作逻辑

点击展开詳情

1. 核心Agent角色（必备+可选）

  • 管理型Agent（总指挥）：需配置最优模型（Cloud OPS 4.6），负责任务分发、工作流记录、团队协作协调，需具备框架熟悉度与记忆更新能力
  • 代码型Agent（程序员）：负责Python代码编写/调试，提示词需精准（含依赖导入、文件编辑、安全红线），推荐身份设定为"文艺复兴科技西蒙斯"或动漫角色（如佐助）
  • 量化型Agent（分析师）：需配置knowledge文件夹存储因子知识，记录已验证/未验证结论，避免幻觉，核心工作是策略设计与回测分析
  • 审查型Agent（风控）：独立审核代码正确性、策略过拟合风险，审核结果分级（P0必改/P1可选改），要求对事不对人、交叉验证
  • 可选Agent：数据类（数据爬取/清洗）、美工类（图表/PPT生成）

2. Agent协作核心

团队共享空间（公告栏+工作流文件）+ 独立工作空间（SO文件/身份文件/Memory文件），管理Agent通过共享空间分发任务，子Agent完成后自动记录成果，避免Token浪费

龙虾核心坑点与解决方案

  • 坑点1：记忆丢失（上下文过长/Session分叉）→ 解决方案：Agent回复前加名字（检测失忆）、锁死SessionID、心跳文件注入记忆（避免Memory文件频繁更新）
  • 坑点2：Token消耗过快→ 解决方案：用200K上下文模型（而非1M）、关闭不必要心跳、拆分大任务、缓存重复请求（Cloud缓存消耗仅1/10）
  • 坑点3：Cloud API无法在OpenCore调用→ 解决方案：通过OAuth授权绕过、搭建中转路由、直接调用Cloud Code CLI
  • 坑点4：程序卡住→ 解决方案：先检查服务器状态→Token余量→Session上下文是否超限，超限则通过管理Agent清理上下文

龙虾量化回测工作流设计

点击展开詳情

1. 核心流程（自然语言→回测落地）

  1. 需求输入：用户/管理Agent提出自然语言策略需求（如"优化纯多策略，规避低流动性币"）
  2. 配置生成：量化Agent将需求转化为JSON配置文件，调用Python程序验证配置有效性
  3. 回测执行：代码Agent执行回测（加入推送机制，完成后自动通知，无需Agent守护）
  4. 结果分析：量化Agent分析回测数据（IC有效性、参数高原/孤峰、亏损特征）
  5. 策略优化：根据分析结果迭代策略，更新工作流与操作手册

2. 关键文件输出

  • 工作流文件：记录团队协作流程与角色分工
  • 量化工程师操作手册：回测命令、文件读取规范、踩坑记录
  • 风控审核手册：过拟合判断标准、历史大跌参考周期、问题库

3. 效率优化技巧

5分钟定时检查程序状态（Python脚本实现）、推送消息自动删除上下文、超过300行代码拆分为小块编辑

Agent提示词设计核心原则

1. 代码型Agent提示词要点

  • 核心要求：代码可直接运行、含完整依赖导入、生成requirements.txt与readme、直接编辑文件（不输出代码文本）
  • 安全红线：禁止RM命令（丢入垃圾桶）、禁止删除数据库表/分支、敏感操作需白名单校验
  • 协作要求：不确定时直接询问，避免无效尝试，超过300行拆块编辑

2. 通用设计原则

身份明确（如"量化工程师西蒙斯"）、能力限定（避免越权）、语气适配（动漫角色增强协作感）、提示词精简（避免上下文冗余）

前端/后端适配与实盘衔接

  • 前端选择：自主开发前端（WebSocket对接飞书/Discord）＞命令行（实盘可视化更清晰）
  • 消息路由：通过@符号区分不同Agent，私聊走固定Session，群聊每日重置Session（减少上下文冗余）
  • 实盘衔接：A股/币圈实盘需前端可视化监控，避免命令行刷新导致的信息遗漏，通过API白名单控制Agent操作权限

成本控制与常见问题解答

1. 成本控制

月均Token成本：Cloud Max会员（约675刀）可覆盖，公益站API可进一步降低成本，避免1M上下文模型（Token消耗翻倍）

2. 高频问题

  • 非程序员入门：无需深度学习前后端，了解核心逻辑后让Agent自主开发，仅需review成果
  • 向量数据库是否必要：数据量少（＜10万条）时无需，用MD文件+索引即可，数据量大时再考虑
  • 国产模型适配：MinMax适合写代码，千问适合管理，Deepseek（开源免费）可作为备选

🔍 底層邏輯與框架

点击展开詳情

1. 核心思维模型：角色分工与流程固化

模拟真实量化团队协作模式，将复杂任务拆解为"管理分发→执行（代码/量化）→审核→优化"的闭环，通过文件记录（工作流/手册）解决Agent记忆丢失问题，实现知识沉淀与流程复用

2. 因果递進关系

模型选择不当→Token消耗高/效果差；Agent角色模糊→协作混乱；工作流不清晰→回测效率低；记忆管理缺失→重复劳动多。核心解决路径：先固化角色与工作流，再优化细节（提示词/API调用）

3. 关键隐喻与案例

「动漫团队隐喻」：卡卡西（管理Agent）→小樱（数据Agent）→佐助（代码Agent）→鸣人（量化Agent），通过角色自带的能力互补，减少协作提示词成本；案例：用该配置成功捕捉STO等妖币行情，A股医疗板块提前预判

4. 量化回测底层逻辑

将自然语言需求转化为机器可执行的JSON配置，通过"生成→验证→回测→分析→优化"的自动化流程，减少人工干预，同时通过独立审查Agent避免策略过拟合与危险操作，确保回测可靠性

✅ 實作步驟 Checklist

  1. 步骤1：环境搭建与模型选择

    1.1 部署龙虾（OpenCore），优先选择稳定版本（不盲目更新），配置WebSocket对接飞书/Discord；1.2 选择模型组合（推荐Cloud+GPT备用），获取API密钥（公益站/官方订阅）；1.3 配置服务器（≥4C4G），预留足够存储（半年-1年数据）。

    卡關點：避免使用本地模型，Cloud API调用问题通过OAuth或中转路由解决
  2. 步骤2：多Agent角色配置

    2.1 创建管理Agent（模型：Cloud OPS 4.6），设定身份为"量化团队总指挥"，配置工作流记录权限；2.2 创建代码Agent（模型：GPT 5.4），提示词包含安全红线与代码规范；2.3 创建量化Agent（模型：千问），搭建knowledge文件夹存储因子知识；2.4 创建审查Agent（模型：MinMax），设定审核分级标准。

  3. 步骤3：工作流设计与文件固化

    3.1 编写量化回测工作流文件（需求输入→配置生成→回测→分析→优化）；3.2 生成操作手册与风控手册，明确回测命令、过拟合判断标准；3.3 配置团队共享空间与独立工作空间，设置文件读写权限。

  4. 步骤4：量化回测实操验证

    4.1 输入自然语言需求（如"优化币圈纯多策略，规避低流动性标的"）；4.2 触发管理Agent分发任务，量化Agent生成JSON配置，代码Agent执行回测；4.3 审查Agent审核回测结果，量化Agent分析亏损特征与参数稳定性；4.4 迭代优化策略，更新工作流与手册。

    卡關點：回测时启用推送机制，避免Agent持续守护消耗Token
  5. 步骤5：坑点规避与效率优化

    5.1 配置Session锁死与心跳文件，解决记忆丢失问题；5.2 关闭1M上下文模型，改用200K+缓存机制，降低Token消耗；5.3 编写Python脚本实现5分钟定时检查程序状态，自动清理冗余上下文；5.4 测试API调用稳定性，配置多API备用方案（公益站轮换）。

🤖 AI 補充建議

【AI 建議】 初期调教Agent时，优先固化工作流与提示词，用简单策略（如均线策略）验证协作逻辑，再逐步复杂场景（多因子策略），避免一开始就陷入细节优化。
【AI 提醒】 避免让单一Agent身兼数职（如代码+量化），会导致上下文冗余与角色混淆，严格按"一事一Agent"原则配置，仅管理Agent可跨角色协调。
【AI 建議】 Token成本控制可采用"分层策略"：核心Agent（管理/代码）用付费模型，辅助Agent（数据/美工）用公益站API，回测任务在非高峰时段执行（降低API调用拥堵概率）。
【AI 提醒】 实盘对接前，务必让审查Agent审核所有API调用权限，设置操作白名单（如仅允许查询持仓，禁止批量下单），避免Agent误操作导致损失。
【AI 建議】 知识沉淀优先使用MD文件+数据库索引，而非向量数据库，除非需语义搜索（如海量研报检索），中小规模数据用简单存储方案更高效、低成本。
